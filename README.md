# Daleel

Daleel is an accessibility-focused, Arabic-first platform intended to help people with disabilities discover learning opportunities, scholarships, and inclusive employment resources.

## Repository layout

This repository keeps the frontend and backend on separate branches so each can be worked on and deployed independently:

- **Frontend branch:** [`frontend`](https://github.com/mhdhossam/DALEEL_FULL/tree/frontend) — React, TypeScript, and Vite.
- **Backend branch:** [`backend`](https://github.com/mhdhossam/DALEEL_FULL/tree/backend) — Django and Django REST Framework.
- **Main branch:** project documentation and the workflow that assembles and verifies the two component branches.

The split workflow copies the matching source directories from [DALEELFULL](https://github.com/mhdhossam/DALEELFULL), then applies setup, test, and configuration fixes. See [Implementation results](docs/IMPLEMENTATION_RESULTS.md) for the fixes and actual verification status.

## Clone one component

### Frontend

```bash
git clone --branch frontend https://github.com/mhdhossam/DALEEL_FULL.git daleel-frontend
cd daleel-frontend
npm ci
npm run dev
```

The Vite development server proxies `/api`, `/data`, and `/media` to `http://127.0.0.1:8000`. Start the backend separately for API-backed features.

### Backend

```bash
git clone --branch backend https://github.com/mhdhossam/DALEEL_FULL.git daleel-backend
cd daleel-backend
python -m venv .venv
# Activate .venv, then install:
python -m pip install -r requirements.txt
```

Copy `.env.example` to `.env`, replace the example values, then run:

```bash
python manage.py migrate
python manage.py check
python manage.py runserver
```

By default, the backend uses SQLite and allows local frontend development origins only. For production, configure a unique `DJANGO_SECRET_KEY`, `DEBUG=False`, `ALLOWED_HOSTS`, `CORS_ALLOWED_ORIGINS`, and PostgreSQL credentials if PostgreSQL is used. Never commit real secrets or production data.

## Verification

The component branches include a `VERIFICATION.md` file generated by the split workflow, documenting the real command outcomes. A source-inspection summary is available in [docs/IMPLEMENTATION_RESULTS.md](docs/IMPLEMENTATION_RESULTS.md); it distinguishes passing checks from checks that failed or could not run.
